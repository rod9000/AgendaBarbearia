# Corrigir Redis + Evolution API v2.3.7

## Problema

A Evolution API v2.3.7 está logando `redis disconnected` infinitamente e o `sendText` trava (timeout). O envio de mensagens falha por causa disso.

### Causa Raiz

Nós estamos usando variáveis de ambiente **erradas** no `docker-compose.yml`:

| Nós usamos (ERRADO)      | A API espera (CORRETO)           |
|--------------------------|----------------------------------|
| `REDIS_ENABLED: "true"`  | `CACHE_REDIS_ENABLED: "true"`    |
| `REDIS_URI: redis://redis:6379"` | `CACHE_REDIS_URI: redis://redis:6379"` |

Confirmado no `env.example` oficial da Evolution API:
```
CACHE_REDIS_ENABLED=true
CACHE_REDIS_URI=redis://localhost:6379
CACHE_REDIS_PREFIX_KEY=evolution-cache
CACHE_REDIS_TTL=604800
CACHE_REDIS_SAVE_INSTANCES=true
```

## Plano de Correção

### 1. Atualizar `docker/evolution/docker-compose.yml`

Trocar as variáveis de ambiente do Redis:
```diff
- REDIS_ENABLED: "true"
- REDIS_URI: redis://redis:6379
+ CACHE_REDIS_ENABLED: "true"
+ CACHE_REDIS_URI: redis://redis:6379
+ CACHE_REDIS_PREFIX_KEY: evolution-cache
+ CACHE_REDIS_TTL: 604800
+ CACHE_REDIS_SAVE_INSTANCES: "true"
+ CACHE_LOCAL_ENABLED: "true"
+ CACHE_LOCAL_TTL: 86400
```

### 2. Recriar containers

```bash
docker compose down --remove-orphans
docker compose up -d
```

### 3. Reconectar instância WhatsApp

Após os containers subirem:
- Acesse `http://localhost:8080/manager`
- Reconecte a instância "Agenda" escaneando o QR Code

### 4. Testar envio

Confirmar que:
- Logs não mais mostram `redis disconnected`
- `sendText` retorna resposta em vez de timeout
- Mensagem chega no WhatsApp

## Arquivos modificados

- `docker/evolution/docker-compose.yml` — variáveis de ambiente do Redis

## Verificação

1. `docker logs evolution_api --tail 10` → sem erros de Redis
2. `curl -X POST http://localhost:8080/message/sendText/Agenda ...` → retorna JSON com sucesso
3. Mensagem chega no celular
